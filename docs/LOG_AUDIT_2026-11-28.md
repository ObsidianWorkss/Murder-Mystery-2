# MM2 diagnostic log audit — November 28, 2026

## Evidence reviewed

30 existing client-side diagnostic JSON exports from the connected game session, plus live combat and juke counters. The exports cover repeated round IDs, partial snapshots, and save-on-reload copies, so **events across files are not guaranteed unique**. Several historical exports reached the 600-event retained-preview cap. The pre-rc.64 events that were already discarded cannot be recovered by a later script update.

| Observed event category | Entries across 30 exports |
| --- | ---: |
| Attack requests | 74 |
| Knife feedback events | 152 |
| Gun feedback events | 33 |
| Gun skip events | 115 |
| Style status events | 115 |
| Events labeled 'Eliminated' by older clients | 87 |

The last category **does not mean 87 confirmed kills or deaths**. An earlier observer classified a missing character, a respawn, and some fake-death states as eliminations. Incoming shooter identity and server-validated hit outcomes are not available from these JSON records. Unanswered gun requests also remain unconfirmed, not missed.

## Recurring problems and changes

1. **Loss of early events in long rounds.** Previously only the latest 600 events were exported. Future rounds are archived in numbered batches of up to 150 events; the normal export JSON retains its 600-event preview and adds an `Archive` manifest listing the batch files, total observed count and completeness. The archival and summary files remain local in `MM2Universal/diagnostics`. When analysing a match, read every `Archive.Files` entry and de-duplicate by event `N` if combining archived chunks with the preview.
2. **Character absence misrepresented as an elimination.** New logs use `Health zero` or `Character unavailable` with a nearby opponent as *context*, never as proof of who fired or who eliminated the player.
3. **Role identity drift.** The last confirmed Murderer/Sheriff/Hero/Innocent role is preserved across temporary Unknown updates within that same round, reducing incorrect opponent classifications.
4. **Overcounted approaches.** An opponent moving toward the player for one uninterrupted second previously produced multiple "approaches." The counter now increments only on entry to an approach episode, with a one-second minimum separation between episodes.
5. **Misleading shooter juke rewards.** Gaining a few studs while still exposed to a Sheriff's gun cannot establish a successful dodge. Learning now requires that the shooter no longer has a directly observable clear line before treating separation as a positive result.
6. **Knife cursor fallback.** Repeated logs show throws made without a confirmed clear assisted target; this may be normal manual aiming. The diagnostic now counts these separately, without inventing successful hits or treating all of them as aim misses.
7. **Blocked corner jukes and unsafe 360 spins.** The prior rc.63 safety checks remain active. Limited 3.8-stud lanes and visible Sheriff/Hero threats were identified in earlier death timelines; the script does not force those unsafe automatic actions.

## Limitations and verification

All event streams remain **client observations**. The recorder does not see an opponent's private button presses, authoritative server hit decisions, or a complete projectile trajectory. A nearby Sheriff at the time of a character loss is not automatically the killer. Event archival completeness depends on the client's local `writefile` capability; any failed writes, dropped data, or mid-round upgrade appear explicitly in the export.

Source-extracted regression tests cover buffering, ordered batch writes, retriable errors, role preservation, continuous-approach debouncing and conservative shooter-aware juke grading. Live shooter-survival improvement still requires real rounds; there is no valid guarantee of winning every engagement.
